## What actually animates

There are no embedded animation clips. Existing animation operates on the **whole world anchor groups**, procedural scene elements, camera and focus light. Dish, server, portal and hologram submeshes do not independently animate in the source scene.

Orbit position starts with `[cos(angle)*radiusX, sin(angle)*radiusY, cos(angle)*depth]`, transformed by an orbit-plane quaternion built from Euler **YXZ**. Angle is `phase + elapsed*speed + scrollMotionProgress*0.66`. World Y gets sinusoidal bob. Three pairwise collision-separation passes keep projected centers at least 2.72 apart while no world is selected.

| World | Radii X/Y; depth | Inclination/yaw/roll | Phase; speed; bob | Idle Y spin amplitude/speed/phase |
| --- | --- | --- | --- | --- |
| Designs | `3.2 / 1.68; 1.08` | `[0.38,-0.2,-0.08]` | `0.38; 0.082; 0.075` | `0.18 / 0.16 / 0.25` |
| Labs | `3.52 / 1.94; 1.3` | `[-0.46,0.42,0.16]` | `2.42; 0.066; 0.09` | `0.16 / 0.13 / 2.1` |
| Shop | `3.34 / 1.78; 1.18` | `[0.58,0.2,-0.22]` | `4.52; 0.074; 0.08` | `0.18 / 0.145 / 4.2` |

Hover pauses elapsed orbit advancement and enlarges the hovered model to 1.14. Inspection moves the selected world to its focus position and scale; background worlds shrink to 0.58 and move 2.4 back in Z. Center W shrinks to 0.52 and moves to Z -2. The selected inner inspection group supports drag yaw/pitch (pitch ±1.05) and wheel/pinch scale 0.85–1.35.

Procedural support geometry consists of three colored LineLoops (144 full / 72 compact points, default opacity 0.15), deterministic depth particles (190 full / 86 compact), and an invisible 1.58-radius sphere per world for pointer hit testing. Do not expose those invisible hit spheres as authored model parts. Particles drift very slowly. The scene shifts right and shrinks as editorial copy arrives (scroll 0.2–0.5); camera Z moves 8.9→11.4. Handoff begins at 0.84 and eases orbit motion to a stop. Full quality adds subtle pointer camera parallax.

## Reuse recommendation

1. Reuse the verified existing web derivatives and their embedded textures unchanged. Keep a provenance manifest mapping each served file to its source path, bytes and hash. Avoid re-exporting, reducing topology, rebaking or copying unused originals.
2. For a Labs-only breakdown, load just one Labs derivative: full and compact are identical. Reuse its cached GLTF scene/geometry/textures across assembled, exploded, selected and wireframe modes. Clone only scene objects and materials that require independent mutation. A second exported model file for each view is unnecessary.
3. For all three worlds, use compact files initially in the OS-sized viewer, with optional full Designs/Shop files only if required. This preserves the actual scene while reducing transfer. Keep one URL for the identical Labs tiers. Center W is only needed if retaining the universe composition.
4. Create temporary semantic groups from verified Labs name prefixes, preserving each node's local transform. Store original positions/quaternions/scales and apply explode offsets relative to them; reset cleanly. Do not describe these new grouping controls as animation already present in the original model.
5. Keep the source GLTFLoader + Meshopt pipeline, normalization, Standard/Physical materials, authored transparency/emissive settings, environment and light rig. An OS window may change camera framing, but should retain model identity and the supplied details.
6. Keep a single Canvas and one mounted scene per viewer; hide/select children or alter their material view without creating additional model downloads. Do not dispose cache-owned geometry or textures when closing one view. Dispose only locally owned material clones, procedural helpers and renderer resources.

The existing pipeline already produces these derivatives without simplification, joining, deduplication, material consolidation or topology changes. It uses meshopt medium, position 16-bit, normal/tangent 12-bit and UV 14-bit quantization; WebP quality 90 for color/emissive, lossless WebP for data maps; compact caps images at 1024 with Lanczos3. The existing manifest reports preserved topology/material signatures, validated bounds and successful Three loader checks. This audit separately confirmed runtime file hashes, structure and embedded resources; it did not rerun those build-time validation commands.
