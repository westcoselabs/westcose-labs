# WestCose Pocket OS — Mobile Creative Direction Brief

**Project:** WestCose Labs  
**Experience:** WestCose Pocket OS  
**Document Type:** Mobile Creative Direction Brief  
**Status:** Approved Creative Direction  
**Platform Scope:** Mobile web  
**Relationship:** Mobile counterpart to WestCose Labs OS  
**Primary Format:** Interactive portfolio presented as a fictional smartphone operating system

---

## 1. Project Overview

WestCose Pocket OS is the mobile version of the WestCose Labs portfolio experience.

The desktop site is presented as a fictional personal computer operating system with folders, applications, files, draggable windows, games, utilities, and Easter eggs. The mobile site should belong to that same world, but it must not behave like a shrunken desktop.

Instead, the mobile experience should feel like a custom WestCose-built smartphone operating system inspired by the familiarity and nostalgia of early iPhone interfaces.

The mobile site begins with a lock screen, opens into a two-page home screen, and presents portfolio sections as full-screen applications. It should feel immediately understandable to phone users while remaining visually distinct, playful, and recognizably connected to WestCose Labs OS.

The concept should combine:

- Familiar smartphone interaction patterns
- Early iPhone and late-2000s mobile nostalgia
- Dark neumorphic interface design
- WestCose visual attitude
- Modern mobile usability
- Subtle system humor
- Full-screen app navigation
- Real browser routes and shareable project pages

The mobile experience should feel like a believable fictional device rather than a novelty skin placed over a standard website.

## 2. Core Creative Concept

### WestCose Pocket OS

WestCose Pocket OS is a fictional mobile operating system installed on a custom WestCose Labs phone.

Projects, games, experiments, services, social profiles, contact actions, system settings, and archived material appear as mobile applications.

The experience includes:

- A brief startup screen
- A custom lock screen
- A horizontal slide-to-unlock interaction
- Two swipeable home-screen pages
- A fixed four-app dock
- Custom neumorphic app icons
- Full-screen app experiences
- Native SMS and phone actions
- Long-press app menus
- Small system widgets
- Funny notifications
- Mobile-specific Easter eggs

The mobile OS should feel inspired by the structure of an iPhone home screen, but it must remain an original WestCose Labs interface.

It should not reproduce Apple branding, Apple application icons, or exact iOS interface components.

## 7. Neumorphism UI Direction

Neumorphism is the primary component language.

The mobile interface should look as though icons, buttons, widgets, and controls are molded from the same physical material as the device surface.

### Surface model

The base material should resemble:

- Matte graphite
- Dark molded plastic
- Soft rubberized hardware
- Powder-coated device surfaces
- Dark blue-gray resin

Avoid:

- Chrome
- Mirror gloss
- Excessive transparency
- Hard metallic edges
- Bright neon outlines
- Overly realistic glass

### Raised elements

Use raised treatment for:

- App icons
- Dock container
- Dock app buttons
- Primary buttons
- Slider handles
- Lock-screen shortcut buttons
- Notification cards
- Toggle handles
- Long-press menu cards

Raised elements should use:

- A subtle upper-left highlight
- A soft lower-right shadow
- Rounded edges
- Limited elevation
- No harsh black drop shadows

### Recessed elements

Use recessed treatment for:

- Widget content wells
- Search or filter fields inside apps
- Settings sliders
- Toggle tracks
- Progress bars
- Lock-screen unlock track
- App icon wells inside the dock
- Selected segmented controls
- Text fields

Recessed elements should appear gently pressed into the surface rather than outlined.

### Pressed states

When tapped, controls should visibly depress.

Pressed states should:

- Reduce the outside shadow
- Increase the inner shadow
- Dim the upper highlight
- Lower the control slightly
- Respond immediately
- Avoid excessive bounce

### Glow usage

Blue glow should be limited to:

- Active app icons
- Current home-screen page indicator
- Selected settings
- Running states
- Progress indicators
- Notification badges
- Focus states
- Hidden or unlocked content

Glow should be subtle and localized.

## 10. Browser and Viewport Rules

WestCose Pocket OS is delivered through a mobile browser and must account for real browser UI.

### No simulated top status bar

Do not create a fake top bar containing:

- Time
- Cellular signal
- Wi-Fi
- Battery
- Carrier information

Users already see this in their actual phone interface. Duplicating it would reduce usable space and weaken the illusion.

The lock screen may display a large central clock, but no second miniature status bar should appear.

### Fixed home-screen height

The following screens should not vertically scroll:

- Startup
- Lock screen
- Home Page One
- Home Page Two

These screens should always fit within the visible browser viewport.

Only full-screen application content may scroll vertically.

### Visual viewport

The implementation should use the current visual viewport rather than assuming a fixed screen height.

The layout must respond when:

- Safari collapses or expands its toolbar
- The URL interface changes height
- The phone rotates
- The page is installed as a standalone web app
- Safe-area insets change

### Bottom browser allowance

The custom dock must sit above the mobile browser toolbar.

It should:

- Respect the safe-area bottom inset
- Preserve a fixed visual gap above browser controls
- Avoid being obscured by Safari’s URL bar
- Move lower when running in standalone mode
- Never touch the physical bottom edge of the screen

## 11. Experience Flow

### Step 1: Startup

A short startup sequence introduces the system.

Suggested copy:

```text
WESTCOSE LABS
Pocket OS v1.0

Starting unnecessary background processes…
```

The startup should:

- Last no longer than two seconds
- Be skippable
- Appear once per session by default
- Be disabled when reduced motion is active
- Avoid delaying access to the portfolio

### Step 2: Lock screen

The user arrives on the lock screen.

The lock screen includes:

- Large time
- Date
- Vertical wallpaper
- One or two notifications
- Slide-to-unlock control
- No fake status bar
- No vertical scroll

### Step 3: Home Page One

After unlocking, the user lands on the primary home screen.

The page contains:

- Two top widgets
- Core app grid
- Two-page indicator
- Fixed four-app dock
- No vertical scroll

### Step 4: Home Page Two

The user swipes horizontally or taps the second page dot.

The second page contains:

- Games
- Entertainment
- Social apps
- Archive material
- Secondary utilities

### Step 5: Full-screen app

Selecting an app expands it to occupy the full app viewport.

The active app includes:

- Visible back button
- App title
- Scrollable app content where needed
- Real route
- Browser-history support
- Clear return to home

### Main elements

- Large time
- Current date
- Wallpaper
- One or two notification cards
- Horizontal slide-to-unlock control
- Optional two shortcut buttons
- Subtle WestCose Pocket OS branding

The clock should be large and visually central.

It should not duplicate the device status bar styling.

Possible treatments:

- Large modern numerals
- Soft embossed type
- Blue accent on AM or PM
- Slight analog shadow
- Optional alternate clock styles in Themes

### Unlock interaction

Use a horizontal control labeled:

```text
slide to explore
```

The control should:

- Move horizontally
- Avoid native swipe-up conflicts
- Feel recessed and tactile
- Provide haptic-like visual feedback
- Include a tap-to-unlock accessibility option
- Reset if not completed

### Shortcut buttons

If used, lock-screen shortcut buttons may open:

- TV
- FightClub
- Projects
- Games

Avoid simulating Apple flashlight and camera controls.

## 18. Messages and Phone

The generic Contact app should not exist on mobile.

Contact is represented by Messages and Phone.

### Messages

Messages launches the user’s native SMS app.

Target:

```text
sms:+16127417277
```

Approved message direction:

> Hey Brandon, I found WestCose Labs and I have a project that might actually be cool.

Alternate message:

> Hey Brandon, I found WestCose Labs and I promise this is not a “make it pop” request.

The final implementation should use the SMS URI format supported by the target browser and device.

### Phone

Phone opens the native dialer.

Target:

```text
tel:+16127417277
```

### Long-press actions

#### Messages

- Start Message
- Copy Number
- Copy Email

#### Phone

- Call Brandon
- Copy Number
- Send Message Instead

No fake permission prompt should appear.

## 19. Full-Screen App Navigation

Every application should open full screen.

### App header

The standard app header should include:

- Back button
- App icon
- App name
- Optional share button
- Optional overflow menu

### Back behavior

At the root of an app:

- Back returns to the correct home-screen page.

Inside nested content:

- First back returns to the app index.
- Second back returns home.

The browser back action should match the visible back-button behavior.

### Back control

Use a visible upper-left control such as:

```text
‹ Home
```

The back control should remain visible while app content scrolls.

### No swipe-up-to-home

Do not introduce a custom swipe-up gesture.

It would conflict with:

- Native phone gestures
- Browser controls
- Installed web-app behavior

The visible back control is the primary navigation method.

## 31. App Opening and Closing Motion

Applications should expand from their icons into full screen.

### Opening sequence

1. Icon depresses.
2. The icon’s accent color expands softly.
3. The app surface grows toward full screen.
4. The app header appears.
5. The home screen dims behind the transition.

### Closing sequence

1. App content fades slightly.
2. The app contracts toward its home-screen icon.
3. The correct page is restored.
4. The dock and page indicators return to focus.

### Motion qualities

- Fast
- Soft
- Tactile
- Familiar
- Slightly nostalgic
- Not an exact iOS reproduction

Avoid:

- Excessive bounce
- Long transitions
- Constant floating
- Heavy parallax
- Glitch effects on normal navigation

- Opening a project updates the route

- Direct links open the correct full-screen app

- Returning home restores the correct page

The fictional OS should sit on top of real semantic routes.

## 40. Final Creative Direction Summary

WestCose Pocket OS is the mobile counterpart to WestCose Labs OS.

It should feel like a custom WestCose take on an early smartphone operating system, presented through a dark neumorphic visual language.

The approved experience includes:

- A brief startup
- A custom lock screen
- Horizontal slide-to-unlock
- One or two funny notifications
- Two swipeable home pages
- A fixed four-app dock
- Full-screen applications
- Visible back navigation
- Native Messages and Phone actions
- Notes replacing README
- Settings with themes, recycle, screen time, and focus modes
- Separate social apps
- Mobile-specific humor
- Real routes and browser history
- No fake top status bar
- No vertical scrolling on system screens
- No terminal, browser, media player, voice assistant, or permission parody

The final experience should feel:

- Familiar enough to understand immediately
- Original enough to avoid imitation
- Funny enough to feel human
- Polished enough to impress
- Clear enough to function as a professional portfolio
- Flexible enough to expand over time

The guiding rule is:

> **WestCose Pocket OS should feel like the mobile device that belongs beside the WestCose Labs desktop computer—not the desktop squeezed onto a phone.**
